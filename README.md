# 机场冬季运行协同推演平台

面向机场运控席位的冬季运行协同沙盘：把 **跑道摩擦、降雪强度、除冰/清扫车辆、航空器起降窗口、机翼防冰有效时间** 放进同一个逐分钟推演模型；工作人员可重新划定跑道关闭区、调整清扫顺序、延后航空器，系统立刻重新推演跑道可用时间及其连锁影响；若调整导致防冰失效、车辆侵入起降区或两条跑道在交叉点冲突，会在**空间视图与时间线上同时定位**。每一套处置方案都保存真实执行进度，页面刷新或服务重启后不会退回最初计划。

## 运行

```bash
node server.js          # 零依赖，Node 18+；默认 http://localhost:4173
PORT=8080 node server.js
```

数据落盘在 `data/plans.json`（原子写入），无外部数据库、无需 `npm install`。

## 推演模型（`public/js/engine.js`）

- **时间**：T0 起 4 小时、分钟粒度；两条跑道各 6 个分段，在第 2/3 段交界处相交。
- **降雪剖面**：三段可编辑（晴/小雪/中雪/大雪），决定分钟级摩擦衰减率与防冰液有效时间（大雪 15′、中雪 25′、小雪 45′）。
- **摩擦系数 μ**：每段独立演进，低于 0.30 不可起降；降到 0.40 自动安排二次清扫，清扫完成恢复到 0.80+。
- **车辆调度**：每跑道两台车（除冰车/清扫车），按“初扫顺序 + 二次清扫紧迫度”并行派活，作业期间车辆位置实时上屏。
- **起降窗口**：航班必须同时满足 ① 全段摩擦达标、② 本跑道无作业车辆、③ 另一跑道航班不占用交叉点；搜索不到窗口时——
  - 进港：等待上限 15 分钟，到点强制复飞/备降，并检测此刻是否有车辆侵入、是否与另一跑道航班在交叉点冲突；
  - 离港：除冰（10 分钟）后必须在防冰有效时间内起飞，超时返回除冰坪重做，最多 2 次，仍失败则取消并报“防冰失效”。

## 三类冲突的双通道定位

| 告警 | 空间视图 | 时间线 |
| --- | --- | --- |
| 防冰失效 | 飞机停在除冰坪、红色告警环闪烁 | 除冰块后的黄色“防冰有效区间”耗尽处红色倒三角 |
| 车辆侵入起降区 | 跑道分段上作业车辆闪红环 | 车辆任务条与航班窗口重叠时刻红色倒三角 |
| 双跑道交叉冲突 | 交叉点斜框脉冲闪烁 + 红色定位环 | 两条跑道航班窗口重叠时刻红色倒三角 |

点击任一告警（或航班/车辆/分段）即完成空间视图与时间线的联动定位，视图时钟跳到事件时刻。

## 真实执行进度如何不回退

- “执行/步进”推动的是**真实时钟** `now`，每个 tick 都通过 `/api/plans/:id/tick` 落盘。
- tick 时从推演结果中固化已完成的清扫分段、已结束的航班、已发生的告警（`state.js: advanceAndRecompute`），再以这些为 **locks** 重推演未来。
- 人工调整（关闭区/顺序/延后）只作用于尚未发生的任务：已完成初扫的分段在 UI 上不可重新关闭，后端另有 `validateAgainstLocks` 兜底；已结束的航班整单锁定。
- 刷新页面/重启服务后从 `data/plans.json` 恢复 `now + locks`，再重算未来视图，历史不退回。
- “另存方案”复制当前真实进度用于横向对比；“重置执行”才会放弃历史。

## 目录

```
server.js              零依赖 HTTP 服务 + 方案持久化 API
data/plans.json        方案真实进度落盘
public/index.html      三栏运控大屏
public/js/engine.js    推演核心（纯函数，前后端共用）
public/js/state.js     真实执行状态机 / 锁定重推演
public/js/geo.js       机场几何与运动轨迹
public/js/mapview.js   空间视图（SVG）
public/js/timeline.js  时间线 Gantt + 摩擦曲线
public/js/editor.js    左侧调整面板
public/js/app.js       编排、API 客户端、联动
```
